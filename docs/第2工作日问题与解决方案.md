# 安灯语音播报 WinForms 项目——第 2 工作日问题与解决方案

## 一、项目进度概况

- 计划周期：5 个工作日
- 当前进度：第 2 个工作日
- 项目目标：使用常驻 Windows 车间电脑上的 WinForms 程序替代操作不便的 PDA 播报页面，在不长期占用主界面的情况下，自动获取 MES 安灯播报任务并通过车间喇叭进行中文语音播报。
- 当前阶段成果：本地提示音和中文 TTS 已验证；MES 登录、车间解析、待播报任务轮询、播放次数回写、托盘最小化和异常重试控制已经形成基本闭环。

## 二、第 2 工作日重点问题与解决方案

### 1. 待播报接口返回“异常信息：null”

**问题表现**

程序能够登录 MES，日志也显示“MES 登录成功”，但调用 `/sys/voiceBroadcast/getNotBroadcastRecord` 后持续报错：

```text
请求地址 '/sys/voiceBroadcast/getNotBroadcastRecord'，发生异常。
异常信息：null
```

**原因分析**

C# 默认将请求模型序列化为 `WorkshopIdList`、`State`，而 Java 接口 DTO 使用 `workshopIdList`、`state`。Java 后端未正确接收到车间列表后，继续执行 `workshopIdList.contains(...)`，容易产生空指针异常。全局异常处理没有返回具体堆栈，因此客户端只看到 `null`。

**解决方案**

- 不再直接使用 C# PascalCase 模型作为请求体。
- 显式使用 Java 接口要求的小驼峰字段：`workshopIdList`、`state`。
- 播报次数回写也统一使用 `id`、`broadcastedNum`。
- 客户端继续保留完整接口错误日志，后续异常可结合 Java 控制台堆栈定位。

**处理状态：已解决并通过构建。**

### 2. 客户端调用了参考后端不存在的确认接口

**问题表现**

客户端最初按更可靠的原子确认思路调用 `/system/voiceBroadcast/confirmPlayed`，但当前 `xy-mom` 源码中不存在该接口，实际联调会出现 404 或确认失败。

**原因分析**

WinForms 初始设计与现有 PDA/Java 后端的接口版本不一致。PDA 当前使用两个既有接口分别更新次数和完成状态。

**解决方案**

- 未达到计划播报次数时调用 `/system/voiceBroadcast/addBroadcastedNum`。
- 达到计划播报次数时调用 `/system/voiceBroadcast/broadcastCompleted`。
- 只有提示音和中文文本完整播放成功后才回写次数。
- 播放失败、暂停或取消时不更新数据库，避免把未播放内容误记为已播放。

**处理状态：已解决并与现有 PDA 流程对齐。**

### 3. 未选择车间时，前后端对“全部车间”的理解不一致

**问题表现**

WinForms 将车间设置设计成可选项，但参考后端不能可靠处理空的 `workshopIdList`，可能出现空指针或“选择的车间没有对应产线”。

**原因分析**

语音任务主要关联产线，后端需要先根据车间 ID 查询产线 ID。参考接口还使用车间 ID `0` 表示包含未绑定产线的公共任务，空数组并不等于全部车间。

**解决方案**

- 指定车间名称时：登录后查询车间列表，将中文名称精确转换为车间 ID。
- 未指定车间时：自动读取全部车间 ID，并附加 `0`，覆盖全部车间产线和未绑定产线的公共任务。
- 保留旧版 `WorkshopIdList` 作为兼容配置。
- 车间名称匹配失败时明确提示，不静默扩大播报范围。

**处理状态：已解决，待使用真实车间数据继续验证范围准确性。**

### 4. 接口持续失败时无限重试，程序看起来像“卡死”

**问题表现**

接口返回错误后，客户端每隔数秒无限请求。日志不断增长，界面长期显示连接异常，用户容易认为程序已经卡死，也会给 MES 服务增加无效请求压力。

**原因分析**

配置中虽然已有 `MaxRequestRetryCount`，但原播报循环没有使用该配置，异常后只执行固定间隔重试。

**解决方案**

- 增加连续失败计数，默认上限为 3 次。
- 重试间隔使用 `NetworkRetrySeconds`，默认 5 秒。
- 单次 HTTP 请求保留 20 秒超时，避免请求永久等待。
- 达到上限后停止自动请求并进入暂停状态。
- 状态栏明确显示“连续失败已达上限，已暂停”。
- 按钮同步显示为“继续播报”；用户排除网络、配置或后端问题后可手动恢复。
- 点击继续时清零计数；任意一次查询成功后也自动清零计数。

**处理状态：已解决并通过构建。**

### 5. 本地语音测试不应依赖 MES 配置

**问题表现**

开发和部署初期经常尚未准备好 MES 地址、账号或数据库数据。如果语音初始化与 MES 连接强绑定，会妨碍车间电脑先验证喇叭、提示音和中文语音包。

**解决方案**

- 本地提示音和中文 TTS 与 MES 轮询解耦。
- MES 未配置时，程序显示“本地播报测试就绪”，仍可测试提示音和中文文本。
- 只有 MES 地址和登录凭据完整时才启动任务轮询。
- 中文语音初始化失败时给出明确提示，要求安装 Windows `zh-CN` 中文语音。

**处理状态：已解决。**

### 6. PDA 与 WinForms 同时运行可能重复播报

**问题表现**

现有接口采用“查询待播报任务—本地播放—回写次数”的方式，没有任务领取或终端锁定。如果 PDA 页面和 WinForms 同时消费相同车间任务，双方可能在回写前读取到同一条记录并重复播放。

**当前解决方案**

- 车间正式使用 WinForms 后，不再同时打开 PDA 的语音播报页面。
- 通过车间范围配置减少不同终端之间的任务重叠。
- 文档和部署要求中明确“一批任务只由一台播报终端消费”。

**后续建议**

如果未来需要多台终端并行工作，应由 Java 后端增加原子领取/确认机制，例如记录终端编号、领取时间和版本号，避免仅依靠客户端约定。

**处理状态：当前通过部署约束规避，后端增强列为后续项。**

### 7. 从托盘退出后窗口消失，但进程无法结束

**问题表现**

程序最小化到系统托盘后，通过右键菜单选择“退出程序”并确认，托盘图标和窗口虽然消失，但 `AndonVoiceBroadcaster.exe` 仍驻留在任务管理器中。该问题基本可以稳定复现，只能通过任务管理器强制结束进程。

**影响与风险**

- 用户容易误以为程序已经退出，实际仍占用系统资源。
- 再次启动时会触发单实例保护，提示程序已经运行。
- 后台可能继续持有 HTTP、TTS 或音频资源，影响下一次启动和车间播报稳定性。
- 强制结束进程无法保证当前播放和日志写入得到正常收尾。

**原因分析**

原退出事件在 WinForms UI 线程中同步执行：

```csharp
_coordinator.StopAsync().GetAwaiter().GetResult();
```

如果退出时正在执行 MES HTTP 请求、提示音播放或中文 TTS，UI 线程会同步等待后台任务结束。后台停止过程又可能依赖异步延续或音频回调，最终造成窗口已经进入关闭流程，但消息循环无法正常退出的情况。

**解决方案**

- 将窗体退出事件改为异步安全退出，不再在 UI 线程无限同步等待。
- 用户确认退出后立即隐藏并禁用托盘入口，防止重复触发退出。
- 主动取消播报循环、当前 HTTP 请求、提示音和中文朗读。
- 最多等待播报协调器 5 秒，正常结束时按顺序完成清理。
- 超过 5 秒后记录警告，不再无限阻塞，继续释放协调器、HTTP 客户端、TTS、提示音播放器和托盘图标。
- 清理完成后关闭主窗体，并显式结束 WinForms 消息循环。
- 增加退出状态提示“正在安全退出”，便于用户了解程序正在收尾。

**验收方法**

分别在以下状态从托盘执行“退出程序”，确认任务管理器中的进程在约 5 秒内消失：

1. MES 未配置、程序处于本地测试就绪状态。
2. MES 已连接、当前没有待播报任务。
3. 正在轮询或接口出现超时。
4. 正在播放提示音。
5. 正在朗读中文文本。
6. 已达到最大重试次数并处于暂停状态。

**处理状态：已解决并通过 Debug 构建，待车间电脑进行多场景退出验收。**

### 8. 车间设置提示与实际输入能力不一致

**问题表现**

界面原来只显示“车间名称（可选）”，容易让用户误以为不能使用已经掌握的车间 ID；如果只把提示文字改成“ID 或名称”，原代码仍会把数字当成名称查询，造成提示与实际行为不一致。

**解决方案**

- 设置项名称改为“车间 ID 或名称（可选，逗号分隔）”。
- 输入内容按逗号、中文逗号或分号拆分。
- 可解析为非负整数的内容直接保存为车间 ID。
- 非数字内容作为车间名称，通过 `/mes/md/workshop/listAll` 精确解析。
- 支持纯 ID、纯名称和混合输入，例如 `211,装配车间`。
- 留空时自动使用全部车间及未绑定产线的公共任务。
- 自动解析得到的运行时车间列表与用户配置分离，避免设置窗口出现大量系统自动填充的 ID。

**处理状态：已解决并通过 Debug 构建。**

## 三、当前正确的接口流程

1. `POST /loginWithNoCode`：使用账号密码登录并获取 Token。
2. `GET /mes/md/workshop/listAll`：获取车间并解析播报范围。
3. `POST /sys/voiceBroadcast/getNotBroadcastRecord`：查询 `state = 0` 的待播报任务。
4. 播放 `AlarmMusic.wav` 提示音。
5. 使用 Windows 中文 TTS 朗读任务 `content`。
6. 未达到 `voiceNum`：调用 `POST /system/voiceBroadcast/addBroadcastedNum`。
7. 达到 `voiceNum`：调用 `POST /system/voiceBroadcast/broadcastCompleted`。
8. 没有任务时按配置周期继续轮询；连续异常达到上限后暂停。

所有需要鉴权的请求均携带：

```http
Authorization: Bearer <token>
```
