# AndonVoiceBroadcaster 设计方案与核心理念

## 1. 功能背景

AndonVoiceBroadcaster 是部署在车间固定 Windows 电脑上的常驻语音客户端，用于替代需要长期打开的 PDA 播报页面。程序从 MES 获取安灯语音任务，依次播放提示音和中文语音，并在完整播放后更新播报次数及完成状态。

当前方案的核心目标：

- 复用 MES 现有语音任务和确认接口，不新增客户端数据库。
- 支持按车间筛选任务，并按创建时间顺序串行播报。
- 保证“实际完整播放”与“MES 次数确认”顺序一致。
- 支持暂停、继续、切换设置、托盘运行和开机启动。
- 网络、音频或系统组件异常时可控暂停，并保证程序最终可以退出。

## 2. 业务对象与程序组成

### 2.1 核心业务对象

- `VoiceBroadcastTask`
  - MES 语音播报任务。
  - `content` 为播报内容。
  - `voiceNum` 为计划播报次数。
  - `broadcastedNum` 为已确认次数。
  - `state=0` 且已确认次数不足时，任务仍为待播报。
- `WorkshopOption`
  - MES 车间 ID 与名称，用于解析客户端播报范围。
- `AppSettings`
  - 保存 MES 地址、车间范围、轮询间隔、TTS 参数和启动选项。
- `MesCredentials`
  - 保存 MES 登录账号和密码，与普通配置分开存储。

### 2.2 主要程序组件

- `MainForm`
  - 负责主窗口、托盘菜单、系统设置和程序生命周期。
- `BroadcastCoordinator`
  - 负责登录、车间解析、任务轮询、顺序播放和次数确认。
- `MesApiClient`
  - 负责 Token、HTTP 请求、JSON 解析和 MES 接口错误处理。
- `SoundService` / `SpeechService`
  - 分别负责 WAV 提示音和 Windows 中文 TTS。
- `SettingsService`
  - 负责普通配置和加密凭据的加载与保存。
- `FileLogger`
  - 负责按天记录运行日志，并同步显示到主界面。

### 2.3 状态口径

任务状态：

- `state=0`：待播报或尚未达到计划次数。
- `state=1`：已完成播报。

客户端状态：

- 正在连接 MES
- 运行中
- 正在播报
- 已暂停
- 连续失败已达上限
- 正在应用新设置
- 正在安全退出

暂停、切换设置和退出属于正常控制操作，不作为播放故障处理。

## 3. 业务流程

### 3.1 程序启动

1. 使用全局互斥量保证同一台电脑只运行一个实例。
2. 加载普通设置和当前 Windows 用户的加密凭据。
3. 初始化日志、提示音和 `zh-CN` 中文语音。
4. MES 配置不完整时只开放本地音频测试。
5. MES 配置完整时启动后台协调器并登录 MES。
6. 根据设置决定是否最小化到系统托盘。

### 3.2 车间范围与任务查询

- 设置支持车间 ID、车间名称或两者混合输入。
- 名称通过 `/mes/md/workshop/listAll` 精确解析为车间 ID。
- 未设置车间时，自动加载全部车间 ID，并加入 `0` 以覆盖未绑定产线的公共任务。
- 名称无法匹配时明确报错，不静默扩大播报范围。
- 待播报任务通过 `/sys/voiceBroadcast/getNotBroadcastRecord` 查询。
- 任务先按 `createTime` 升序，再按 `id` 升序，保证 FIFO 播报。

### 3.3 单次播报与次数确认

一条有效播报按以下顺序执行：

1. 播放 `AlarmMusic.wav`。
2. 检查是否暂停、切换设置或退出。
3. 使用 Windows 中文 TTS 朗读任务内容。
4. 再次检查是否取消。
5. 未达到 `voiceNum` 时调用 `/system/voiceBroadcast/addBroadcastedNum`。
6. 达到 `voiceNum` 时调用 `/system/voiceBroadcast/broadcastCompleted`。

以下情况不回写次数：

- 提示音或中文语音未完整播放。
- 用户暂停、保存新设置或退出程序。
- 播报内容为空。
- 本地音频播放失败。

设计上优先避免“实际没有播完，但 MES 已记录为完成”。

### 3.4 确认异常恢复

语音已经播放完成，但确认接口可能发生超时、断网或 Token 失效。此时客户端先查询任务实际状态：

- 后端次数已经增加：视为前一次确认成功。
- 后端次数未增加且任务仍待播报：再确认一次。
- 后端状态与本地预期不一致：停止处理并重新查询任务列表。

该流程用于降低“确认成功但响应丢失”造成的重复播报。

### 3.5 暂停与切换设置

- 点击暂停后立即停止当前提示音或 TTS。
- 每个播放阶段结束后都会重新检查暂停状态，避免暂停后继续启动下一阶段。
- 正常取消返回未完成结果，不通过异常控制业务流程。
- 当前次数不写回 MES，任务保持待播报。
- 保存新设置时，在后台停止旧协调器并释放旧服务，主界面保持响应。
- 旧服务停止后，使用新的车间范围重新登录和查询。

### 3.6 网络失败与退出

- 单次 HTTP 请求超时为 20 秒。
- 请求失败后按配置间隔重试。
- 连续失败达到上限后自动暂停，等待用户检查后手动继续。
- 普通关闭主窗口只隐藏到托盘，不停止播报。
- 托盘确认退出后取消轮询和当前播放：
  - 协调器最多等待 5 秒。
  - HTTP、TTS 和提示音资源最多等待 2 秒。
  - 10 秒后仍未结束时执行进程级兜底退出。

退出超时主要用于隔离 Windows TTS、音频驱动等外部系统组件永久阻塞的风险。

## 4. 页面与配置说明

### 4.1 主窗口

- 展示运行状态、终端编号、车间范围和当前任务。
- 展示按 FIFO 排序的待播报任务列表。
- 提供暂停/继续、测试提示音、测试中文语音和系统设置。
- 界面下方显示本次运行日志。

### 4.2 系统托盘

- 打开主窗口。
- 开始或暂停播报。
- 执行本地音频测试。
- 打开系统设置和日志目录。
- 确认后真正退出程序。

### 4.3 配置存储

- 普通配置：`config/appsettings.json`。
- 登录凭据：`data/credentials.dat`。
- 凭据使用 Windows DPAPI `CurrentUser` 加密，只能由保存它的 Windows 用户解密。
- 开机启动写入当前用户注册表，不要求管理员权限。

## 5. 关键业务边界

- 同一协调器内只允许串行播报，不并行混播多条任务。
- 空内容任务保留待播报，不自动确认。
- 暂停或取消发生在任意阶段时，本次次数均不确认。
- 车间名称无法解析时停止查询，不能自动改成全部车间。
- MES 配置不完整时不启动轮询，但允许测试本地声音。
- 旧车间配置停止后才能按新范围启动协调器。
- Windows 音频取消和资源释放不能阻塞 UI 或退出线程。
- 日志按天保存，并按配置天数清理历史文件。

## 6. 当前实现限制与依赖

- 客户端依赖现有 MES 登录、车间、任务查询和次数确认接口。
- 登录账号需要车间查询和语音播报相关权限。
- 车间必须存在有效产线，否则后端会返回“选择的车间没有对应产线”。
- 车间电脑必须安装可用的 `zh-CN` Windows 中文语音。
- `TerminalCode` 当前只用于界面和日志，还没有参与后端任务领取。
- 现有后端没有任务领取或租约机制；PDA 与 WinForms、或两台终端同时消费相同范围时，仍可能重复播报。
- 当前通过部署约束保证同一批任务只由一台终端消费；多终端场景最终需要后端提供原子领取和幂等确认。

## 7. 核心设计理念

1. **完整播放后再确认**  
   MES 状态不能领先于真实播报；提示音或语音未完成时不增加次数。

2. **正常取消不是异常**  
   暂停、换配置和退出应快速、安静、可恢复，不使用异常表达正常业务控制。

3. **外部组件必须有时间边界**  
   网络、TTS 和音频均可能失效或阻塞，客户端必须提供超时、后台取消和最终退出兜底。

4. **客户端可靠性不能替代后端原子性**  
   客户端负责单机顺序和播放一致性；多终端并发消费最终应由 MES 后端通过任务领取、版本校验或幂等确认解决。
